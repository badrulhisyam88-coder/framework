{# ==================== VERIFICATION ==================== #}

Verification Guidance

The Server-header version reported above can be misleading. Distros backport security fixes without bumping the version, and nginx bundled inside Java appliances, vendor products, or Docker images won't appear in rpm/apt at all. Use the appropriate verification path for each finding based on its Backend column.

Universal: interrogate the running binary

Works regardless of how nginx was deployed (OS package, container, vendor bundle, source build):

1. Find the master pid ps -ef | grep '[n]ginx: master'
2. Resolve the binary path readlink /proc/<pid>/exe
3. Print exact version + build flags <path> -V 2>&1

Backend-specific routing

java/atlassian, java/jira, java/confluence, java/bitbucket nginx is bundled by Atlassian. Check the vendor's security advisory and apply the vendor patch — do not try to swap the binary.
java (generic), java/tomcat, java/jetty nginx may be a separate reverse proxy or part of an appliance. Verify with the running-binary method above; if it's bundled, check the appliance vendor's advisory.
php, php/wordpress, php/drupal, php/laravel nginx is most likely an OS package fronting PHP-FPM. Check distro patch status: rpm -q --changelog nginx (Rocky/RHEL) or apt-cache policy nginx (Debian).
node, python, ruby nginx is most likely an OS package fronting an application server. Check distro patch status as above.
unknown Backend could not be fingerprinted from the response. Use the universal running-binary method.

Exploitability check (config-level)

{{ cve.cve_id }} additionally requires a specific configuration trigger to be exploitable. After confirming the version is vulnerable, check the running config:

Search for the trigger pattern grep -rE 'rewrite\s+.*\$[0-9]+.*\?' /etc/nginx/

The exploit fires when a rewrite directive is followed by another rewrite/if/set directive that contains an unnamed PCRE capture ($1, $2, …) and a ? in the replacement string. If no config matches that pattern, the host is "potentially vulnerable" but not currently exploitable.
