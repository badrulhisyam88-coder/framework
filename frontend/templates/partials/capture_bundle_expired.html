{# ── Explanation ──────────────────────────────────────────── #}

This Capture bundle was created during a previous backend session and is no longer available. Captured artifacts (request/response bodies, JWTs, post-exploit responses) live in memory only and are cleared on backend restart.

The Capture node remains in the graph because it's part of the investigation's persistent lineage. Only its contents were transient.

{# ── Recommended action ────────────────────────────────────── #}
Recommended next step

Re-run the action that produced this bundle to regenerate the artifacts. A direct “Re-run” button is not available from this panel because the bundle expired with the run record that knew which action_kind produced it — click back to the upstream Outcome → Action chain and re-execute the suggestion from the finding panel.

{# ── Detail / debugging ──────────────────────────────────── #}
Why does this happen?

Capture bundles live in the backend's process memory (the _BUNDLES registry in apps/investigation_workspace/capture/bundler.py). This is the same lifecycle as _RUNS in execution/runtime.py — persistent forensic memory was deferred to keep restarts cheap during early development. Long-running investigations will lose bundle contents on every backend restart.

Persistence (writing bundles to disk / DB so they survive restart) is tracked as a future PR.
